# ValutaTrade Hub

Учебный валютный кошелёк с пользователями, портфелями, виртуальными сделками
и отдельным Parser Service. Автор: David Zakharyan, группа М26-555.
Репозиторий: `finalproject_Zakharyan_M26-555`. Версия: **0.3.0**.
Все деньги виртуальные. Реальные котировки используются только для симуляции.

## Установка и запуск

Python 3.12+, uv; для файловой блокировки парсера требуется macOS/Linux (`fcntl`).
Из корня проекта:

```bash
make install
make lint
make test
make run
```

Эквивалент установки: `uv sync --locked --dev`.
Запуск: `uv run valutatrade` или `uv run python main.py`.
Команда `valutatrade-parser` запускает парсер отдельно от интерактивного Core.

## API-ключи

ExchangeRate-API требует персональный ключ из аккаунта на
[exchangerate-api.com](https://www.exchangerate-api.com/).
На macOS/zsh его можно ввести без отображения и без записи значения в историю:

```zsh
read -s "EXCHANGERATE_API_KEY?ExchangeRate API key: "
export EXCHANGERATE_API_KEY
printf '\n'
```

Переменная доступна приложению, запущенному из этого терминала. После открытия
нового терминала её нужно задать снова. Ключи не включаются в исходники или README.
`.env` исключён из Git, но автоматически не загружается.

CoinGecko сначала можно попробовать без ключа. Если доступ требует авторизацию,
получите Demo API key и аналогично задайте `COINGECKO_API_KEY`. Он передаётся
заголовком `x-cg-demo-api-key`. Pro-ключ предназначен для другого тарифа/эндпоинта.
Не присылайте ключи в чат и не вставляйте их в запись демонстрации.

## Первый сценарий

Команды внутри `make run`:

```text
update-rates
show-rates
register --username alice --password 1234
login --username alice --password 1234
deposit --amount 5000
buy --currency BTC --amount 0.001
show-portfolio
sell --currency BTC --amount 0.0005
get-rate --from EUR --to USD
show-rates --top 2
show-rates --currency RUB
show-rates --base EUR
exit
```

Для уже созданного пользователя пропустите register. При перезапуске нужны
только login и обновление устаревших курсов. Пользователи и портфели сохраняются.

- `deposit` пополняет виртуальный USD-баланс, изначально портфель пустой.
- `buy --amount` — количество покупаемой валюты; USD списывается по курсу из кеша.
- `sell` списывает валюту и зачисляет USD. Изменения двух кошельков сохраняются вместе.
- Покупка/продажа USD за USD запрещена; для USD используйте deposit.
- Суммы положительные и конечные; bool, NaN, Infinity запрещены.
- buy/sell/show-portfolio/deposit требуют входа; просмотр и обновление курсов — нет.
- Балансы float соответствуют учебному заданию. Комиссий и реальных переводов нет.

## Parser Service

### Источники и направление курса

- CoinGecko `/simple/price` запрашивает BTC, ETH, SOL одним запросом, используя
  ID `bitcoin`, `ethereum`, `solana`. Результат — цена одной монеты в USD.
- ExchangeRate-API `/latest/USD` запрашивает EUR, GBP, RUB. Реальное поле ответа —
  `conversion_rates`; `rates` поддерживается для совместимости с примером задания.
  Ответ содержит USD→валюта, поэтому для EUR_USD, GBP_USD, RUB_USD берётся **1 / rate**.
  Например, USD_EUR=0.927 означает EUR_USD≈1.07875, а не 0.927.

Официальные контракты:
[ExchangeRate-API](https://www.exchangerate-api.com/docs/standard-requests),
[CoinGecko Demo](https://docs.coingecko.com/demo/reference/simple-price).

`ParserConfig` хранит URL, списки валют, соответствия тикеров и ID, пути, таймаут
(10 секунд). Ключи читаются из окружения при создании, исключены из repr.
База на этом этапе — USD. Поддерживаемый реестр: USD, EUR, GBP, RUB, BTC, ETH, SOL.

`BaseApiClient.fetch_rates()` — абстрактный контракт словаря `{пара: число}`.
Клиенты проверяют HTTP-статус, JSON, полноту выбранных валют, конечность и
положительность курсов. 401/403/429, таймаут, неверный ключ и неполный ответ
превращаются в `ApiRequestError`. URL с ключом и сырое тело ошибки не выводятся.
HTTP-перенаправления отключены, автоматических повторов нет.

`RatesUpdater.run_update(source=None)` последовательно запрашивает клиентов.
Сбой одного источника не отменяет другой. CLI сообщает о частичном успехе и
числе обновлённых пар. Если все источники недоступны, история и кеш остаются
без изменений. Неуспешный или не полностью проверенный ответ не сохраняется.

### Команды

```text
update-rates
update-rates --source coingecko
update-rates --source exchangerate
show-rates
show-rates --currency BTC
show-rates --top 2
show-rates --base EUR
get-rate --from BTC --to EUR
```

`show-rates` выводит только свежие данные. `--top` — N самых дорогих
**криптовалют по цене единицы**, а не по капитализации. Можно сочетать фильтры.
Для кросс-курса к EUR необходимы свежие пары обеих валют к USD.
Пропущенные устаревшие/недоступные пары сообщаются отдельно.

Core Service не выполняет сетевые запросы при get-rate/buy/sell/show-portfolio.
Он использует прямой, обратный либо кросс-курс через USD. Если подходящих свежих
данных нет, предлагает `update-rates`. Никакой незаметной подстановки DemoStub нет.

### Форматы хранения и время

`data/rates.json` — снимок:

```json
{
  "pairs": {
    "BTC_USD": {
      "rate": 100.0,
      "updated_at": "2026-10-18T08:00:00Z",
      "source": "CoinGecko"
    }
  },
  "last_refresh": "2026-10-18T08:00:01Z"
}
```

Число в этом примере вымышленное. `exchange_rates.json` — JSON-массив измерений:
`id`, `from_currency`, `to_currency`, `rate`, `timestamp`, `source`, `meta`.
ID имеет формат `BTC_USD_<ISO-UTC timestamp>`; одинаковый ID не добавляется повторно.
Конфликт содержимого при одинаковом ID считается ошибкой. В снимке побеждает
только более новое время, сравниваемое как datetime, а не строка.

**timestamp/updated_at — время успешного получения и проверки ответа.** TTL
(300 секунд по умолчанию) измеряет возраст локального получения. Время обновления
самого значения поставщиком отдельно сохраняется в `meta.provider_updated_at`,
если оно доступно; также сохраняются raw_id, request_ms, status_code и etag.
Получение свежего ответа не означает, что поставщик изменил котировку:
фиатный API может обновлять значения значительно реже.

Каждый JSON сохраняется через временный файл, fsync и os.replace. Писатели
Parser Service защищены межпроцессной блокировкой `data/rates.lock` и RLock.
История записывается раньше снимка. Это **не транзакция двух файлов**: если вторая
запись не удалась, старый снимок остаётся читаемым; следующий успешный запуск
восстановит его из истории. Повреждённые JSON не заменяются пустыми документами.
История пока не ограничена по размеру и целиком читается при обновлении.

### Обновление по таймеру

Однократный отдельный запуск:

```bash
uv run valutatrade-parser --once
uv run valutatrade-parser --once --source coingecko
```

Периодический запуск в открытом терминале, остановка Ctrl-C:

```bash
uv run valutatrade-parser --interval 240
```

Интервал — пауза после завершения запроса, допустимо 60–86400 секунд. Запросы
не перекрываются. После ошибки API цикл продолжается с той же паузой.
По умолчанию пауза 300 секунд; выбирайте её вместе с TTL и квотой своего тарифа.
Никакие cron/launchd-службы не устанавливаются автоматически. Для экономии
лимита можно обновлять фиат вручную отдельно от криптовалют.
В режиме `--once` полный/частичный сбой даёт ненулевой код завершения.

## Модели, исключения и конфигурация

`User` хранит ID, имя, SHA-256(password + salt), соль и дату регистрации.
`User.create()` создаёт соль; `change_password()` меняет её вместе с паролем.
`get_user_info()` не содержит хеш/соль; открытый пароль не сохраняется.
`Wallet` инкапсулирует неотрицательный баланс; `Portfolio` объединяет кошельки
и владельца. CLI считает стоимость через актуальный RateService.
Модельный `Portfolio.get_total_value()` допускает явно переданные курсы;
его старые учебные значения по умолчанию не используются в CLI-сделках.

`Currency` — ABC с `get_display_info()`. `FiatCurrency` содержит issuing_country,
`CryptoCurrency` — algorithm и market_cap. Капитализация в реестре — учебная,
не загружается парсером и не используется для вычисления цены.
`get_currency()` создаёт объект по коду; коды — 2–5 латинских букв,
имена непустые. CLI нормализует регистр.

| Ошибка | Реакция |
| --- | --- |
| InsufficientFundsError | Доступный и требуемый баланс; портфель не меняется |
| CurrencyNotFoundError | Неизвестный код и список поддерживаемых валют |
| ApiRequestError | Ошибка сети/API либо недоступный кеш; подсказка повторить/обновить |
| ValueError | Некорректные аргументы/данные; CLI продолжает работу |

`SettingsLoader` и `DatabaseManager` — Singleton через __new__ и RLock, без
побочных эффектов при импорте. WalletService использует единое хранилище;
тесты внедряют изолированные базы. `get(key, default)` читает конфигурацию,
`reload()` валидирует её целиком перед заменой. После изменения путей/TTL
перезапустите CLI: существующие сервисы сохраняют параметры конструктора.

Настройки в `[tool.valutatrade]` файла `pyproject.toml` текущей папки:

| Ключ | По умолчанию |
| --- | --- |
| data_dir | data |
| users_file / portfolios_file / rates_file | users.json / portfolios.json / rates.json |
| rates_ttl_seconds | 300 |
| default_base_currency | USD |
| log_file | logs/actions.log |
| log_format / log_level | json / INFO |
| log_max_bytes / log_backup_count | 1048576 / 3 |

Относительные пути считаются от папки конфигурации. Без файла используются
значения по умолчанию относительно текущей папки. Для одной базы запускайте
приложение из одной папки. DatabaseManager блокирует сценарии только внутри
процесса: одновременно используйте один Core-процесс для записи портфелей.
Откат регистрации при ошибке записи второго файла не является crash-safe
транзакцией нескольких файлов. Парсер пишет только историю и снимок курсов.

## Журналы

`logs/actions.log`: `@log_action` записывает BUY/SELL, UTC ISO-время, уровень,
пользователя, код, amount, rate, base, result. При ошибке — error_type/message,
исключение пробрасывается. `verbose=True` добавляет балансы до/после успеха.
Неизвестный курс и невалидная сумма представлены null. Пароли, хеши и соли
не включаются; register/login не журналируются.

`logs/parser.log`: старт обновления, запрос каждого источника, успех/ошибка,
запись и завершение. Формат обоих журналов — JSON Lines. Журнал парсера —
INFO, ротация по 1 МиБ, три резервные копии; торговый журнал настраивается
через SettingsLoader. HTTP URL с ключами не логируются.

```bash
tail -n 5 logs/actions.log
tail -n 10 logs/parser.log
```

## Обновление с версии 0.2.0

Пользователи и кошельки совместимы и сохраняются. Старый плоский кеш читается,
но записи DemoStub больше не используются для сделок. При первом успешном
update-rates снимок преобразуется в формат `pairs`, учебные котировки исключаются.
Перед покупкой/отчётом выполните update-rates; при частичном успехе будут доступны
только загруженные источники и ещё свежие прежние реальные записи.

## Структура

```text
valutatrade_hub/
  core/             # models, currencies, exceptions, usecases, utils, constants
  infra/            # settings, database
  parser_service/   # config, api_clients, storage, updater, scheduler
  cli/interface.py
  decorators.py
  logging_config.py
main.py
pyproject.toml
uv.lock
Makefile
tests/
data/.gitkeep
```

Рабочие JSON, lock-файлы, logs, .env, .venv, dist, pycache и записи cast исключены
из Git. При переносе проекта не копируйте пользовательские базы из чужой папки.

## Проверки и сборка

```bash
make lint
make test
make build
uvx twine check dist/valutatrade_hub-0.3.0*
uv tool install --force dist/valutatrade_hub-0.3.0-py3-none-any.whl
valutatrade
```

Автотесты не требуют ключей и не обращаются в интернет: API подменяются Mock,
котировки задаются в временных базах. Проверяются клиенты, направление курсов,
ошибки, кеш, история, частичный успех, атомарность записи, планировщик, CLI,
Singleton, модели, сделки и перезапуск. Торговые тесты могут писать в локальный
журнал, но не меняют рабочие пользовательские базы.
